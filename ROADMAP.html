The idea in one minute

Chatbots pay very different prices for different AI models (a strong one costs 20–30× a cheap one), but most user messages are easy. We build a middleman that looks at each message and sends it to the cheapest model that is good enough for that kind of message, following the UniRoute paper (Google, ICLR 2026) step by step.

  1. Sort messages into types (free): thousands of real user messages are grouped into K clusters.
  2. Report cards (paid once): 4 models answer 400 graded messages; an AI grader, checked against your labels, marks each answer pass/fail; each model's failure rate per cluster is its report card (paper Eq. 12).
  3. Route: new message → nearest cluster → the model with the lowest failure rate + λ × price.
  4. Safety around it: backup model if one is down, step up to a stronger model if an answer is broken, a cache for repeated questions, logs and a dashboard.
  5. Prove it: 300 messages are locked away from the start and opened once at the end.
Prepare code→Real data in→Small pilot + your labels→ Report cards & router→Gateway→Final test→Report

The phases

8 phases, done in order. Phase 5 (the gateway) runs alongside phases 2–4. Each phase ends with a clear result; the gates are where you approve. Total: about 4 weeks.

Phase 1 · Build and test everything for free (before the data)

~5 days · $0

Goal: when the data arrives, the paid part is "press run", not "write code under pressure".

WP-01

Safe data reader

Reads the chats and hides the live API keys inside them before anything else touches the text.

WP-02

Messages, rules, splits

Turn chats into routable messages; detect menu clicks, images and huge system prompts; split by chat into train / validation / test.

WP-03

Pick the text-to-numbers model

Compare 2–3 local multilingual embedders for speed and Persian quality.

You: look at sample groups in a local page (10 min), approve the choice.

WP-04

Calling models safely

Saves every answer (never pays twice), enforces the $60 cap, resumes after crashes; checks Metis AI is reachable; every call visible in a local MLflow screen.

You: put the Metis AI key in .env.

WP-05

UniRoute, exactly as the paper

K-means, nearest centre, report cards (Eq. 12), routing rule (Eq. 8/11), area under the deferral curve, QNC, the paper's comparison routers; tested on made-up data where the right answer is known.

WP-06

Answering, grading, labeling page

Code for the models to answer like production and for the AI grader to score; the page you will label on.

You: try the labeling page on 5 items (10 min).

WP-07

Dry run

The whole pipeline end to end on the sample with free fake answers, to prove the code works.

~3 days · ~$6

Clustering and routing: exactly as the paper

StepWhat we do (paper reference)
Text representationThe user's message, embedded with a frozen general-purpose text embedder, run locally (§5.1). Never the chatbot's system prompt.
ClusteringK-means on the large unlabeled training messages; K ∈ {3 … N_val/50} = {3…8} (App. G.2).
AssignmentEach message goes to its nearest cluster centre (§5.1).
Report card ΨEach model's plain failure rate in each cluster on the validation set (Eq. 12).
Routing rulePick the model with the lowest Ψk(model) + λ · cost(model) (Eq. 8 / 11).
Choosing KThe K with the largest normalized area under the deferral curve (quality vs cost as λ varies) on validation (App. G.2).
Choosing λSweep λ; pick the point for a quality target or a cost budget (App. E).
ComparisonsAlways-best, always-cheapest, ZeroRouter / Pareto-random, K-NN (paper baselines); reported, UniRoute ships.
New modelAnswer the same 400 validation messages → one new report-card row, no retraining (the paper's main claim; shown as a demo).

How a work session goes

  1. Open a terminal: cd ~/Downloads/RahnemaCollege2026/metis-auto && claude (default model, Opus 5.5).
  2. Type /start: Claude reads the status, tells you in a few lines what it will do, and waits for your OK.
  3. It works on one work package and stops at every approval point.
  4. At the end (or when the context is 60% full) it runs /handoff: updates the status, log and plan, commits to git and pushes to GitHub.
