L3 · When the LLM is called

The router runs only when it pays

About 90% of messages

A rule decides

Cheapest allowed model clearing the quality floor this request needs. No extra call, no added latency.

About 10%, hard or failure-prone

The LLM decides

Reads the evidence and the per-request prices, returns model, backup and a reason. Cut off at 1.5 s, then the rule takes over.

Why the split — the cost of deciding, not of answering

Median cost of answering one message

$0.00015

One router call — 3.3× the median

$0.0005

Asking the LLM on every message would add about 36% to the whole spend. About 80% of messages are cheaper to answer than to deliberate over.

The gate is not complexity alone: if the retrieved evidence shows a failure rate above 10%, the LLM is called even for an easy-looking request.

This is the heart of the approach. The gate has three branches. Greetings, small talk and button payloads go to the rule. So does anything below the complexity threshold with no code, maths or attachment. Everything else goes to the LLM. And there is an override on top: if the retrieved evidence shows models failing more than one time in ten on requests like this, the LLM is called whatever the complexity says. The bars are about the cost of deciding, not the cost of answering — the evaluation section has the end-to-end totals. Finally the guard: if the LLM is slow, errors, returns broken JSON or names a model that is not allowed, the rule decides instead, so a router failure never drops a request.
