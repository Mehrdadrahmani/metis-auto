L4 · Sensitive requests

Health and medicine questions take a safer path

Markers such as medication, illness, pregnancy, cancer, depression and suicide set a flag on the feature card. Three things change, by code, before any model is chosen.

Never from cache

A personalised health answer must never be replayed to another user.

No cheap shortcut

The flag adds 0.12 to complexity, which lifts the quality floor the model must clear.

Reaches the LLM

That same 0.12 clears the gate, so these requests are not routed by the rule.

An empty answer, a refusal or a non-Persian reply is retried once on a stronger model

This check is rules only, with no model call. The LLM judge belongs to the evaluation path, not to every request.

Marker scope today: health and medicine. Banking is not in the list.

Worth being precise here, because it is the kind of claim a judge will test. The sensitivity flag is not checked by the routing gate directly. It works through complexity: the flag adds zero point one two, which is above the gate threshold, so in practice these requests reach the LLM rather than the rule. Two honest exceptions: a message of four tokens or fewer containing a greeting word is classified trivial before complexity is consulted, and if someone raised the threshold above zero point one two the guarantee would disappear. Say never from cache plainly — that one is an explicit rule, not a side effect. And if asked about judging, the answer check is regular expressions, not a model.
